# Demonstration script — around 5 minutes

Do a dry run and read actual values from the app. Every example is fictional. Do not describe simulated benefits as measured upay outcomes.

## Opening (40 seconds)

"Our idea has two connected moments: an agent prepares the right mix of cash and electronic float, and a customer pauses to inspect a payment request. The upay Agent app publicly describes item-wise transactions, real-time statements and commissions. We use those as plausible starting points, while all data shown here is synthetic."

## Agent Planning (90 seconds)

Select Agent. Choose Cash running low. Point to manually counted cash, demo electronic balance and recommendation. Read its actual amount and time. Point to Why this suggestion? and explain that the forecast comes from fictional past cash-in and cash-out requests. Expand Show forecast and replay, then Reveal actual synthetic day to compare the ML suggestion with historical forecasting and doing nothing.

Select Exchange is expensive. The recommendation should keep the balances. Say: "Our costs and commission are assumptions. An exchange moves value between cash and float; it cannot create total capital."

## Payment Safety (100 seconds)

Select Safety. Choose Urgent account reactivation request. Press Review before sending. Show the warning and Where these signals came from. The text was entered by the customer, while first-payment and typical-amount fields come from a fictional sender history. There is no verified complaint or real recipient identity. The index is not a probability of fraud.

Press Request demo review. Switch to Hospital bill (customer checked) and review again. Explain that even a legitimate large payment can receive a warning. Select No prior recipient history to show Insufficient information. No one is labeled a fraudster.

## Evidence and questions (100 seconds)

Select Cases to show the recorded fictional reasons and simulated customer choice. Then select Evidence for the input/source table and measured test results. Explain that the forecast was tested chronologically on later synthetic days; the language model was evaluated on 24 held-out authored sentences. These tests do not validate real-world fraud detection or business impact. A pilot would need approved operational records, full exchange costs, refused-demand logs and reviewed payment outcomes.

## Final check

Run the tests and evaluation with the virtual environment Python in Windows CMD. Rehearse the actual app instead of reading a screenshot. Test the live deployment and video link before submission.
